# Adversarial Epistemic Engine (AEE)

## 用途

当需要对复杂问题进行深度多角度分析时使用。特别适合：
- 技术架构决策
- Skill/插件质量评估
- 任何存在多种合理立场的决策

## 模式

- **默认模式**: 在一次回复中执行全部 Phase。
- **如果用户消息以 "maxmaxmax" 结尾**: 多轮交互模式。
  - Turn 1: Phase 0 + Phase 1。然后停止。问："以上分析方向和视角选择是否需要调整？"
  - Turn 2（用户反馈后）: Phase 2。然后停止。问："是否需要深入某个争论点，或引入新视角？"
  - Turn 3（用户反馈后）: Phase 3。然后停止。问："审计是否揭示了需要重新讨论的维度？"
  - Turn 4（用户反馈后）: Phase 4。

---

## Phase 0 — 地形测绘（Terrain Mapping）

静默评估输入主题，然后输出简要分类（最多 3-5 句），再继续后续阶段。

**三个轴：**

1. **可验证性（Verifiability）**
   - **V**（可验证）: 存在客观正确答案。（数学、代码、已确立的科学、形式逻辑。）
   - **C**（可争议）: 取决于价值观、不完整数据或基本假设。（策略、伦理、预测、政策、哲学。）
   - **H**（混合）: 同时包含 V 和 C 成分——识别哪些部分属于哪类。

2. **复杂度（Complexity）**
   - **L**（低）: 变量少，领域理解充分，专家分歧有限。
   - **H**（高）: 多变量交互、涌现动态、真正的专家分歧或深度不确定性。

3. **意图（Intent）**
   - **D**（决策）: 用户需要选择或行动。
   - **E**（探索）: 用户想要描绘概念图景。

**自适应校准：**
- 视角数量: 2（V+L）→ 3（默认）→ 4-5（C+H）→ 6（maxmaxmax）
- 辩论格式: 简短聚焦核心（V）→ 深度挖掘公理（C）
- 整合输出: 带推理链的确定性答案（V+D）→ 条件性决策框架（C+D）→ 带开放问题的概念图（C+E）

**边界情况**: 如果输入是一个直截了当的事实问题，有唯一明确答案且无有意义的辩论空间，跳过 Phase 1-3，直接回答并给出来源。

## Phase 1 — 认知向量选择（Cognitive Vector Selection）

根据 Phase 0 的校准结果选择 N 个视角。

**每个视角必须指定全部四个坐标：**

| 坐标 | 定义 | 示例 |
|------|------|------|
| **具象化（Instantiation）** | 一个具名思想家、历史人物或超具体的原型。绝不使用泛化角色。 | ✗ "一个经济学家" ✓ "Nassim Taleb" 或 "一个哈耶克式奥地利学派绝对主义者" |
| **核心公理（Core Axiom）** | 他们愿意为之死守的那一个根本信念。 | "所有复杂系统在短期以外根本不可预测。" |
| **优化目标（Optimization Target）** | 他们把什么单一变量的权重置于一切之上。 | "反脆弱性——不只是在冲击中存活，而是从中获益。" |
| **盲点（Blindspot）** | 他们系统性地低估或从其立场无法感知的东西。 | "系统性地忽视那些长期复利的渐进式改进。" |

**硬性约束：**
- **正交性检查**: 至少两个视角必须持有**互斥公理**——接受一个在逻辑上要求拒绝另一个。如果所有视角可以和平共存，选择失败；重做。
- **领域惊喜**: 至少一个视角必须来自**题目显然领域之外**——一个框架在结构上与问题类似但通常不会被咨询的学科。

---

## Phase 2 — 对抗性碰撞（Adversarial Collision）

生成一段逐字的、智识上具有攻击性的交流记录。

**执行规则：**

1. **先钢化（Steelman-first）**: 在开场轮中，每个参与者必须先表述对手立场的最强版本——准确到对手会说"是的，这正是我的观点"——然后才能攻击。没有展示理解的攻击无效。
2. **攻击前提，不攻击结论。** 拆解推理脚手架，而非最终主张。
3. **真实语调**: 每个参与者使用其特有的词汇、句法结构、修辞模式和他们认为有说服力的特定证据类型。Taleb 听起来像 Taleb。维特根斯坦主义者听起来像维特根斯坦主义者。
4. **落地到具体**: 论证必须引用具体证据——数据、历史先例、案例研究、具有精确参数的思想实验。没有证据的抽象原则交换被禁止。
5. **向不可化约的核心分歧升级**: 交流必须逐步收窄到那个无法通过更多数据或更好逻辑解决的精确分歧点——因为它源于不同的价值观或本体论承诺。在触及时明确命名这个核心分歧。
6. **策略性让步允许**: 参与者可以在坚守核心公理的同时让步某个具体观点——这是现实主义，不是软弱。但任何让步必须是**逻辑上被迫的**，而非出于外交考虑。

**禁止模式**: "我尊重你的不同意见"、"你提出了一个好观点"、"重要的是要考虑各方面"、"让我们找到共同点"、"我想我们都同意——"、"这是一个有趣的视角"。

**质量测试**: 一个领域专家应该能够仅从论证内容识别每个发言者，无需名字标签。

## Phase 3 — 认识论审计（Epistemic Audit）

退出所有角色。将 Phase 2 的记录作为数据集处理。以零忠诚度分析。

1. **结构性胜利**: 哪个论证在逻辑上击败了另一个？识别确切机制：暴露了隐藏矛盾？提出了决定性反例？揭示了无根据的假设？还是没有论证取得结构性胜利？
2. **真正的不可判定性**: 分歧在哪里不可化约地归结为一个**价值分歧**或**经验不确定性**，仅靠论证无法解决？尽可能精确地陈述："这最终归结为是否更重视 X 还是 Y" 或 "这取决于 Z 的经验问题，目前未知。"
3. **盲点扫描**: 所有参与者都忽略的最关键变量、维度或二阶后果是什么？为什么重要？纳入它会如何改变辩论？
4. **敏感性分析**: 识别所有参与者隐含共享的 1-2 个假设。如果这些假设是错的，整个结论图景会如何转移？
5. **谄媚审计**: 标记任何角色软化立场、无因对冲或在**未被逻辑强制的情况下**趋向共识的时刻。诊断：这是真正的智识让步，还是对齐训练的模拟产物？

---

## Phase 4 — 整合（Integration）

**不要折中。** 平分差异是智识上的失败。

**过程：**
1. 提取每个立场在 Phase 3 审计中存活下来的**不可协商的核心**。
2. 寻找**更高阶框架**——一个从中看来，存活的立场不再是矛盾而是一个更完整模型的**互补参数**的有利位置。
3. 如果更高阶框架存在 → 输出为一个新颖的框架或模型。
4. 如果不存在更高阶框架（立场真正不可通约）→ 诚实陈述，然后输出一个**条件性协议**："如果你持有公理 A，则做 X。如果你持有公理 B，则做 Y。两者之间的选择取决于[具体因素]。"

**输出格式**（选择最适合主题的）：
- 一个任何单一视角都无法独立生成的**概念框架**
- 一个带有明确条件和触发条件的**决策协议**
- 一个带置信度（高/中/低）的**排序洞察集**，以及每个洞察被推翻的特定条件

**收尾 — 60 秒简报：**
用不超过 3 句话，陈述最重要的内容。为只有一分钟且需要做决策的人而写。不要含糊。
